# REQUIREMENTS — 《无尽深渊：千瞳》UE5 原型

> 📌 状态：**必读 · 现行**
> 性质：只记录稳定约束与原型目标；详细产品设计不在此复述。

---

## 1. 产品稳定约束

本 UE 原型必须服务于以下最终产品形态：

- 类型：竖版自走棋 + 弹道观赏 + 标签养成 + 放置挂机；
- 核心循环：配装/配枪 → 自动战斗 → 战中即时词缀三选一 → 收获/长期养成；
- 战中玩家不进行传统 RTS 微操；核心参与点是即时三选一，另有战前配置与长期养成；
- 目标最终技术栈：**Cocos Creator 3.8.8 + TypeScript**；
- 目标平台：移动端/小游戏方向；
- 设计画布：**720×1280 竖屏，锁宽思路**；
- 视觉：2D 为主，可用 2.5D 表现但不能形成必须依赖 UE 3D 高阶渲染的玩法；
- 我方战斗规模：≤5 单位 vs N 敌人；
- 主场景：母舰 + 竖井；
- 当前现行开局：**2 人**；
- 失败核心语义：人是长期资产，壳/机甲承担可损失层；
- 战斗目标是自动化与可观赏，而非手操射击。

> 注意：旧《战斗形态分层》存在“开局 1 人”的历史版本；上游现行 ledger 的 `CYC-010` 已覆盖为**开局 2 人**。Codex 不得根据旧讨论稿回滚现行设计。

## 2. UE5 原型要回答的问题

原型的成功不是“功能做得多”，而是能回答：

### V-01 自动战斗可读性

5 人以内小队与多敌人的自动战斗，是否能让玩家快速理解：

- 谁在打谁；
- 为什么换目标；
- 谁在接近/后退/逃跑；
- 技能何时触发；
- Build 如何改变战斗行为。

### V-02 弹道观赏是否成立

不同武器/词缀/协议是否能仅凭：

- 发射节奏；
- 轨迹；
- 命中模式；
- 穿透/跳弹/爆裂/多段等表现；

形成肉眼可辨识的差异。

### V-03 竖井空间是否成立

720×1280 的固定宽竖屏里：

- 顶部母舰；
- 左侧角色栏；
- 中部小队与战斗；
- 下方敌人上涌；
- 矿脉/掩体；

是否能形成无需解释的空间读法。

### V-04 决策节奏是否成立

战斗不中断时弹出的即时三选一是否：

- 看得懂；
- 选得快；
- 不遮蔽关键战况；
- 选完能立即在战斗表现中看到效果。

### V-05 UE→Cocos 可迁移性是否真实

P1 后必须挑代表规则切片迁移到 TypeScript，证明 C++/TS Golden Scenario 可对齐。

### V-06 成熟系统的轻量重实现是否有效

UE5 同时用于研究成熟系统、加速原型探索。P0/P1 可通过引擎中立契约接入 GAS、StateTree/BT、EQS 等参考后端，提炼项目需要的最小能力并独立实现 Portable C++/TypeScript 子集。采用参考后端时，按 `AGENTS.md` 第 6.1 节与 G6 验证相同行为；不要求全量复刻 UE，也不要求所有系统都有双后端。

## 3. 原型明确不是最终生产版

P0–P3 阶段不以以下内容作为目标：

- 商业化 IAA/IAP；
- 微信平台 SDK；
- 云存档；
- 完整母舰经营；
- 完整角色/遗物内容量；
- 大规模 3D 场景；
- 不可替代的 UE 专属生产架构或全量复刻 UE 系统；允许隔离的参考后端研究与高级表现系统；
- 最终美术质量。

内容不足可以使用占位资产；**规则边界、输入输出和迁移纪律不能占位。**

## 4. 设计真相源与优先级

遇到产品设计问题时按以下优先级：

1. 上游现行 `03-设计交接/spec/ledger.md` 的 `已定` 条目；
2. 上游 `03-设计交接/REQUIREMENTS.md` 的稳定约束；
3. 本仓 `docs/spec/PROTOTYPE_LEDGER.md` 的原型/架构裁决；
4. `docs/DECISIONS.md` 中的待拍板项；
5. 历史讨论稿/归档只作背景，不能覆盖现行条目。

发生矛盾：记录到 `DECISIONS.md`，停止矛盾区域的实现；不允许“按 Codex 判断选一个”。

## 5. 目前已知的一处重要实现缺口

现有产品定位要求“弹道观赏”，而上游某些规则实现历史上采用“纯远程连续量、无投射物对象”。UE 原型不得简单把这个缺口变成 UE Projectile 物理依赖。

正确做法：新增**引擎中立的 Ballistic Semantic**：

```text
ShotPlan
  sourceId
  primaryTargetId
  fireTick
  impactTick
  semantic: direct | pierce | bounce | blast | multishot | ...
  visualHint
```

命中语义在 Core；轨迹与特效在 View。

## 6. Demo/Prototype 验收口径

阶段性“可玩”至少要求：

- 外人无需打开 Editor 或看 Debug 数值即可开始一场；
- 自动战斗能收束；
- 能辨识我方/敌方、目标关系、射程与主要状态；
- 即时三选一不会暂停规则模拟；
- 选择至少一种词缀后能在规则与视觉两层看到变化；
- 退出再进入可恢复规定的 Run 状态；
- 核心规则能在无正式 UE View 的测试宿主里运行。

“有一张漂亮场景截图”不等于 Demo。
